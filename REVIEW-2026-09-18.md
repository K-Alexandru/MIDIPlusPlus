## Fixed in this pass, each with a test that fails without it

- A custom velocity curve played the table of the curve before it:
  `applyCurve` copied from index 5, the built-in count before S-Curve.
- A velocity curve change while a live note was held left that key down.
- Copy sheet and the sheet editor inherited the last playback speed, because
  `startPlayback` rescales `note_events[i].time` in place.
- A config save that failed retried flat out and pinned a core; it now backs
  off 5 s, and gives up when the config never loaded (no test).

## Performance

Measured on the built shell: idle and focused it uses 2.5 to 3.4% of a core
redrawing identical frames; minimized, 0%.

1. Autoplay injects every batch on a thread-pool thread at normal priority
   and blocks on its future, while the MMCSS thread only waits.
   `PlaybackCore.cpp:740`. Run the batch inline.
2. The autoplay wait is `condition_variable::wait_for`, millisecond grained;
   a high-resolution timer is created at `PlaybackCore.cpp:455` and never
   used. Windows 11 can ignore the 1 ms request for an occluded window, so
   opt out with `PROCESS_POWER_THROTTLING_IGNORE_TIMER_RESOLUTION`. Measure
   lateness first; `LATENCY.md` has no autoplay number.
3. `setThreadToRealTime` raises the process class for good, registers MMCSS
   on the engine worker (which scans folders and parses files) and not on
   the callback threads, and leaks a handle per `MIDI2Key`.
   `MIDI2Key.cpp:15`. Rerun `LatencyTests` after any change.
4. The UI renders continuously and ignores `Present`'s occlusion status.
   `Shell.cpp:335`. Render on input or a snapshot change.
5. `Snapshot()` deep-copies the whole state about 100 times a second while
   playing, and `Panels` calls it nine times a frame.
6. 71 MB of CJK fonts are read into the heap at startup. `Fonts.cpp:30`.
   Map the files instead.
7. `WS_EX_LAYERED` stays set after opacity returns to 100.
