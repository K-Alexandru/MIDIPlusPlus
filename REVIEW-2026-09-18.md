# Bug, UI and performance pass, 2026-09-18

Found by the shell and render suites, `run-native-tests.ps1`, the built shell
driven at 125% against corrupt, empty, Unicode and long-named files, and three
read-only code reviews. The owner asked for all of it fixed the same day.
"Test" names what holds a fix; each was checked by reverting the fix and
watching it fail. "Seen" means checked on the running app.

## Engine

- A custom velocity curve played the table of the curve before it: `applyCurve`
  copied from index 5, the built-in count before S-Curve. Test.
- A curve change, a transpose, a remap or a channel change while a live note
  was held left that key down. `MIDI2Key` now drains its callbacks and releases
  what they hold before it rebuilds its tables. Tests for all four.
- Copy sheet and the sheet editor took note times from the last playback
  speed. Test.
- A `config.json` the player refused was replaced with defaults at launch,
  mappings and curves with it. Defaults are written only where no file
  exists. Test.
- On MIDI output, Stop, Pause, Seek and Load left the synth ringing.
  `release_keys` silences the port there. Test.
- The layout switches dereferenced a null player after a failed startup.
  Test (the mutant dies with an access violation).
- Curve change and AutoVol calibrate reopened the port MidiConnect held.
- A config save that failed retried flat out and pinned a core.
- `a.mid` and `a.midi` shared one sheet name; the destructor could lose its
  wakeup; a failed load did not say which file.
- The shell project never defined `__WINDOWS_MM__`, so RtMidi had no WinMM
  backend there: WinMM devices could not open and every launch logged two
  errors. Seen.

## UI

- Play, Pause and Cancel are one width, and Cancel wears the cancel mark. Seen.
- The anchor tool redrew Linear Fine as an S an eighth of the range low. The
  anchors are now chosen by what PCHIP makes of them. Test, seen.
- A click that moves nothing is not an edit. Seen.
- A drag moves its anchor in the list the drag found, so a shared x cannot
  swap the index and a pass through a neighbour does not stay.
- Ctrl+Z belongs to the main window; a resync cancels a gesture in flight.
- The song title takes the width and the F1 to F4 legend gives way to it; a
  key another program holds is drawn dead, not labelled. Seen.
- TRACK and INSTRUMENT share the width by content. Seen.
- Settings uses the skin's groove and chevrons, and stays on the screen when
  opened from mini at the bottom of a monitor. Seen.
- Export's ticks are the skin's. Seen.
- Track names reach the table as UTF-8, and a harpsichord is a keyboard. Tests.
- A lost graphics device is rebuilt. Seen, by forcing the flag, not a real
  driver reset.
- The collapsed curve combo fits " (edited)" and cannot push Sustain cutoff
  off the panel; state pills have their own ImGui ID.
- Explanatory strings removed. **Owner to read:** the key mapping readout is
  a note, an arrow and a keycap; an empty Files list offers Choose MIDI
  folder; the velocity modifier's conflicts are listed without their
  sentence; the AutoVol calibrate tooltip, "Latest 256 KB", "No engine
  messages", "Waiting for note observations", "Stop hotkey unavailable",
  "Velocity hotkeys unavailable", "Same-name ports kept separate", "Open a
  MIDI file" and the device pill's instruction are gone.
- "Settings in mini shows two rows" was my capture, not the app: the popover
  is its own window there.

## Performance, measured on the built shell

| | before | after |
|---|---|---|
| Idle, focused | 2.5 to 3.4% of a core | under 0.5% |
| Working set | 126 MB | 57 MB |
| Threads | 43 | 30 |
| Live input to hook, p50 | 0.010 to 0.058 ms | 0.017 to 0.026 ms |
| Autoplay dispatch to hook | 0.053 to 0.323 ms | 0.043 to 0.049 ms |

Three loopback runs each through loopMIDI; the latency rows are within noise.

- Frames are drawn on input, a new snapshot or a change of size, and for
  750 ms after; the engine posts `WM_NULL` on publish.
- `Publish` carries the log and telemetry, so `Snapshot()` no longer
  deep-copies the state on the UI thread forty times a second.
- Autoplay injects on its own MMCSS thread; the pool of one thread per core
  is gone.
- Autoplay waits on a high-resolution timer to within 300 us, then spins.
- The process opts out of Windows 11's timer throttling for covered windows.
- `MIDI2Key` no longer raises the process class for good, and registers
  MMCSS on the threads that deliver MIDI.
- The CJK fallback fonts are mapped, not read into 71 MB of heap.
- `WS_EX_LAYERED` comes off at 100% opacity; occlusion is tested without
  drawing.

## Left

- Autoplay scheduling lateness is still unmeasured: `LatencyTests` times
  dispatch to hook, not how late a note starts. The timer change is the
  one that should move it.
- The worker still copies the whole state per publish, 40 times a second
  while playing; `keyMappings`, `rows` and `curves` as `shared_ptr` ends it.
- `track_note_owners` allocates per note in autoplay dispatch.
- A flip-model swap chain, unverified against `LWA_ALPHA` opacity.
- Expanding the velocity editor discards a height the owner dragged to.
- The test projects lack `__WINDOWS_MM__` on purpose (they fake the ports),
  so their output still prints RtMidi's complaint.
