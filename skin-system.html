What you can operate

Strip

Toggles switch. Sustain cycles the fork's three states rather than two, because SustainMode is IG, SPACE_DOWN, SPACE_UP. 88 Keys changes the status bar to 61-key. The gear opens Settings, where the real WinRT, WinMM and Wooting choices, device selector, channel and keyboard timing controls live.

Tracks

Mute and solo work per row, with solo overriding mute the way it does in a DAW. Solo Piano mutes every non-piano part; Unmute All clears it. The status bar counts what is actually silent rather than repeating a number I typed in.

Settings

Three switches that change behaviour, not three switches that look like settings. Solo piano tracks on load fires when you pick a different file. Velocity hotkeys off drops events per note from 1.4 to 1.0, which is the ALT preamble leaving.

Key mapping

Click any key, then press a key on your keyboard: the assignment changes. Paging moves an octave at a time, Full 88 shows the whole board, and the range in the status bar follows.

Fitting a 1080p screen

The problem

Panels had stacked up in the order they were added: file list, transport, tracks, velocity editor, key mapping. That reached 1078 px in Classic and 1210 px in Modern. A 1080p screen with a taskbar leaves about 1000 px, so Modern did not fit and Classic only just did.

Key mapping is its own window

It is set up once, not adjusted while playing, so it does not need to hold height in the window you keep open. As a separate window it is also free to be wider than the main one, which is what black keys needed to become real hit targets.

Velocity starts collapsed

Same reasoning: you tune a curve once, then play. The collapsed header still carries the two things you touch mid-session, the active curve and the sustain cutoff, so collapsing costs nothing you actually reach for.

Tracks never collapses

Tracks was ignored because it was easy to miss, so hiding it behind a tab or a disclosure would repeat the mistake that Solo Piano exists to fix. It stays open, and the height came out of the two panels that could afford it.

Result after the depth rebuild: 635 px in Classic and 728 px in Modern with the editor collapsed, rising to 1009 and 1115 px while it is open. The collapsed state is the default and the one you keep open; Modern with the editor open still wants a taller screen. Tabs would have saved more, but only by hiding Tracks.

Depth, spacing and state

Four surfaces, not one

Every skin defines a canvas, a structural tone for the strip and status bar, a card tone, and an elevated tone for controls, plus a fifth recessed tone for anything you type into, read from or fill up: fields, lists, the track table, the curve graph, slider tracks.

Raised things carry two shadows, a tight contact shadow and a soft ambient one, with a one-pixel top highlight. Recessed things carry an inner shadow. Borders are semi-transparent hairlines rather than solid grey lines.

One 4px scale

4, 8, 12, 16, 24. No one-off values anywhere, including the popover, the steppers and the track table. Radii are concentric: a segment inset by 4px inside a 12px control is drawn at 8px, so nothing looks like a rounded box glued inside another rounded box.

Two deliberate departures from the brief: container padding starts at 12px in Classic and 16px in Modern rather than 24px, and hit targets are 28px and 32px rather than 44px. This is a dense mouse-driven desktop tool sitting beside a running game, not a touch surface.

Accent is 10 percent

Accent means selection, focus, the live curve and the value fills. It is not used to decorate. Toggle state stays green because that is a semantic state, and it always pairs colour with a dot, a label or an icon so colour is never the only signal.

Mute is the clearest case: an unmuted track shows a speaker, a muted one shows a crossed speaker, and the row dims. Reading it does not depend on seeing the tint.

Every control has states

Hover lifts the shadow, active presses the surface in and drops it a pixel, focus draws a ring with an offset, and transitions run at 160ms ease-out. Rows in the file list, preset list and track table share one height rhythm so their baselines line up across panels.

Velocity response: a musical decision, not a graphing exercise

Start with how you really play

The pale histogram is this session's input. It makes the useful question visible: is your normal playing range being squeezed into the middle, or spread across outputs the game can actually express?

See cause and effect live

Each incoming note travels along the curve and reports both values. For example, 72 played → 84 to game. Move across the graph in this mockup to try different input strengths.

Two decisions cover most players

Sensitivity answers “how hard must I play to get loud?” Contrast answers “how far apart should gentle and firm notes feel?” Both explain when you would move them.

The 32 steps stay underneath

You edit a smooth response and the app samples it into the 32 levels MIDI++ already uses. The faint staircase keeps that implementation honest; exact step editing lives behind Advanced.

Presets describe outcomes

Names are paired with a thumbnail and plain-language effect, so “Logarithmic” is no longer a vocabulary test. Pick by the feel you want, then tune from there.

Judge it by comparison

The A/B button flips between the current edit and the previous curve while you play. That is faster and more trustworthy than trying to remember how the last shape felt.

Solo Piano: the feature, and why it's nearly free

The data already exists

TrackControl::TrackInfo in your fork already carries instrumentName, programNumber, channel and isDrums. Nothing new needs parsing.

General MIDI programs 0–7 are pianos. So Solo Piano is: mute every track where programNumber > 7 || isDrums. That's the whole feature.

Mipha's Court is the exact case

Flute over piano. Autoplay types the flute line into the same 88 keys as the piano, so the arrangement collapses. One click drops it.

Tracks needed to say what it's for

You said you ignored the panel because it wasn't clear what it did. It now shows the instrument name with a dot marking piano vs everything else, and a one-line explanation in the header.

It should also run on load

Worth a setting: auto-solo piano tracks when a file opens. Most virtual-piano users want this every time and would never find the button.
